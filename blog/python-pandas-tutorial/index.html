    Chapter 1: Introduction to Pandas

    What is Pandas?

    Pandas is an open-source Python library for working with structured data: data arranged in rows and columns, like a spreadsheet or a database table. It gives you two main objects, the Series (one column) and the DataFrame (a whole table), plus hundreds of methods to load, clean, reshape, combine and summarise them.

    A useful mental model: a DataFrame is a spreadsheet you control with code. Every click you would make in Excel (filter, sort, pivot, VLOOKUP) becomes one line of Python that you can rerun, test and review.

    Why do we need it?

    Suppose you need the average salary per department from a CSV. In plain Python you would open the file, parse each line, convert strings to numbers, build a dictionary of lists, then loop again to average. In Pandas:

    pd.read_csv("employees.csv").groupby("department")["salary"].mean()
    department
Data Science    98500.0
Engineering     97500.0
Product         88000.0
Sales           67000.0
Name: salary, dtype: float64

    One line, and it handles type conversion, missing values and grouping for you. The heavy lifting runs in compiled code (NumPy, and increasingly Apache Arrow), so it is also far faster than a Python loop.

    History and background

    • 2008: Wes McKinney started Pandas at AQR Capital Management to analyse financial data in Python.
    • 2009: released as open source. The name comes from "panel data", an econometrics term for multi-dimensional data.
    • 2020: version 1.0, a stable API after a decade of growth.
    • 2023: version 2.0 added optional PyArrow-backed data types.
    • 2026: version 3.0 made Copy-on-Write the only behaviour and introduced a dedicated string data type by default. Both changes appear throughout this guide.

    What problems does Pandas solve?

    • Reading data from many formats (CSV, Excel, JSON, SQL, Parquet, HTML) into one common structure.
    • Cleaning messy real-world data: missing values, duplicates, wrong types, inconsistent text.
    • Selecting, filtering and transforming data without writing loops.
    • Summarising data by group, the equivalent of SQL's GROUP BY.
    • Joining datasets from different sources, the equivalent of SQL joins.
    • Working with dates and time series: resampling, rolling averages, time zones.
    • Writing the result back out as a report, a file or a database table.

    Features and benefits

    • Labelled data. Rows and columns have names, so df["salary"] reads like English.
    • Automatic alignment. Operations match rows by label, not by position, which prevents a whole class of off-by-one bugs.
    • Missing data handling built into every method.
    • Vectorised operations that run in compiled code.
    • Rich I/O for more than a dozen file formats and SQL databases.
    • Time series tools that came from its finance origins.
    • Ecosystem. Matplotlib, Seaborn, scikit-learn, Jupyter and most data tools accept DataFrames directly.

    Real-world applications

    • Backend development: bulk CSV imports, data migrations, admin report exports. My post on bulk CSV import and export pipelines covers the Django side of this.
    • Data analysis: sales, marketing and product dashboards.
    • Data engineering: ETL steps that clean data before it lands in a warehouse.
    • Finance: price series, returns, risk calculations.
    • Machine learning: feature preparation before training a model.
    • Testing and QA: comparing expected and actual datasets after a migration.

    Chapter 3: Series and DataFrames

    Everything in Pandas is built on two structures. Learn these well and the rest of the library makes sense.

    What is a Series?

    Definition: a Series is a one-dimensional labelled array. It holds values of one data type plus an index: a label for each value.

    Purpose: a Series represents a single column of data, such as all salaries or all order dates. Think of it as a Python list with labels attached, or a dictionary whose values can be used in maths all at once.

    Syntax:

    pd.Series(data, index=None, dtype=None, name=None)

    From a list

    data = [10, 20, 30, 40]
s = pd.Series(data)
print(s)
    0    10
1    20
2    30
3    40
dtype: int64

    The left column is the index. Pandas created 0 to 3 automatically. dtype: int64 says every value is a 64-bit integer.

    From a dictionary

    salaries = pd.Series({"John": 75000, "Alex": 95000, "Sara": 88000}, name="salary")
print(salaries)
    John    75000
Alex    95000
Sara    88000
Name: salary, dtype: int64

    Dictionary keys become the index. The name becomes the column name if this Series later joins a DataFrame.

    From a NumPy array, with a custom index

    scores = pd.Series(np.array([82, 91, 77]), index=["math", "physics", "chemistry"])
print(scores.index)
print(scores.values)
    Index(['math', 'physics', 'chemistry'], dtype='str')
[82 91 77]

    Accessing elements

    salaries["Alex"]                 # by label      -> 95000
salaries.iloc[0]                 # by position   -> 75000
salaries[salaries > 80000]       # by condition
    Alex    95000
Sara    88000
Name: salary, dtype: int64

    Common mistake

    Writing salaries[0] to get the first value. When the index is made of labels, square brackets look up labels, and pandas 3 no longer falls back to positions. Use .iloc[0] for positions and .loc["John"] or ["John"] for labels, so your intent is always clear.

    Series attributes and methods

    print(salaries.dtype, salaries.size, salaries.name)
print(salaries.mean(), salaries.max(), salaries.idxmax())
print(salaries * 1.10)          # a 10% raise for everyone, no loop
    int64 3 salary
86000.0 95000 Alex
John     82500.0
Alex    104500.0
Sara     96800.0
Name: salary, dtype: float64

    salaries * 1.10 is a vectorised operation: Pandas applies it to every value in compiled code. This idea comes back in every chapter.

    What is a DataFrame?

    Definition: a DataFrame is a two-dimensional labelled table with rows and columns. Each column is a Series, and all columns share the same row index.

    Purpose: it represents a whole dataset: a CSV file, an Excel sheet, a SQL query result. Different columns can hold different types (text, numbers, dates).

    Syntax:

    pd.DataFrame(data, index=None, columns=None, dtype=None)

    From a dictionary of lists (most common)

    data = {
    "Name": ["John", "Alex", "Sara"],
    "Age": [25, 30, 28],
}
df = pd.DataFrame(data)
print(df)
       Name  Age
0  John   25
1  Alex   30
2  Sara   28

    Each key becomes a column name and each list becomes that column's values. All lists must have the same length.

    From a list of dictionaries (typical API response)

    rows = [
    {"name": "John", "age": 25},
    {"name": "Alex", "age": 30, "city": "Bengaluru"},
]
print(pd.DataFrame(rows))
       name  age       city
0  John   25        NaN
1  Alex   30  Bengaluru

    Each dictionary becomes a row. Keys missing from a row become NaN ("not a number"), the standard missing-value marker.

    From a list of lists, and from a NumPy array

    pd.DataFrame([["John", 25], ["Alex", 30]], columns=["name", "age"])

rng = np.random.default_rng(seed=42)

    • columns holds the column labels.
    • index holds the row labels. RangeIndex is the memory-efficient default 0, 1, 2 and so on.
    • dtypes shows each column's type. Text columns show str.

    pandas 3 change: the str dtype

    Before pandas 3, text columns had the generic object dtype, which could hold anything. pandas 3 infers a dedicated str dtype backed by PyArrow when it is installed. It is faster and uses far less memory: a million short city names took 55.4 MB as object and 14.4 MB as str in my test. Code that checks dtype == object to find text columns needs updating.

    Tip

    Read ID-like columns such as phone numbers, ZIP codes and account numbers with dtype="str". Otherwise "007" becomes the integer 7 and the leading zeros are gone for good.

    File paths

    A relative path such as "data/orders.csv" is resolved from the current working directory, which is wherever you started Python or Jupyter, not where your script lives. Build paths from the script's location to avoid surprises:

    from pathlib import Path

DATA_DIR = Path(__file__).resolve().parent / "data"
orders = pd.read_csv(DATA_DIR / "orders.csv")

    read_csv also accepts URLs, compressed files (.gz, .zip, detected from the extension) and file-like objects such as io.StringIO.

    Common read errors

    pd.read_csv("employes.csv")
    FileNotFoundError: [Errno 2] No such file or directory: 'employes.csv'

    Check the spelling and print Path.cwd() to see where Python is looking.

    name,age
John,25
Alex,30,extra
    pd.read_csv("bad.csv")
    ParserError: Error tokenizing data. C error: Expected 2 fields in line 3, saw 3

    A row has more fields than the header, usually an unquoted comma inside a value. Fix the export if you can. If you must load it, on_bad_lines="skip" drops those rows, but log how many you lost.

    UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9 in position 13: invalid continuation byte

    The file is not UTF-8. Files exported from older Windows tools are often latin-1 or cp1252: pd.read_csv("latin.csv", encoding="latin-1") read José and São Paulo correctly.

    read_sql() and to_sql()

    read_sql runs a query and returns the result as a DataFrame. It accepts a SQLAlchemy engine or connection for any database, or a plain sqlite3 connection for SQLite.

    import sqlite3

conn = sqlite3.connect(":memory:")
employees.to_sql("employees", conn, index=False, if_exists="replace")

high_earners = pd.read_sql(
    "SELECT name, salary FROM employees WHERE salary > ? ORDER BY salary DESC",
    conn,
    params=(90000,),
)
print(high_earners)
        name  salary
0  Priya  120000
1    Mei  102000
2   Alex   95000

    For PostgreSQL or MySQL, create an engine with SQLAlchemy: create_engine("postgresql+psycopg://user:pass@host/db"), and pass it instead of conn. Read credentials from environment variables, not from the code.

    Security

    Always pass user input through params, never with an f-string inside the SQL. Parameters are sent separately from the query, which prevents SQL injection.

    to_sql options worth knowing: if_exists ("fail", "replace", "append"), chunksize to insert in batches, and method="multi" to send several rows per INSERT. Filter in SQL rather than loading a whole table and filtering in Pandas; the database is better at it. My database optimization guide covers indexing for those queries.

    Chapter 6: Selecting and Accessing Data

    Selection is where most beginners get confused, because Pandas offers several ways to do it. The rule of thumb: use [] for columns, .loc for labels, .iloc for positions.

    Columns

    employees["name"]                  # one column -> Series
employees[["name", "salary"]]      # several columns -> DataFrame

    employees.name (attribute access) also works, but fails for names with spaces or names that clash with methods such as count. Prefer brackets.

    loc[]: select by label

    Definition: .loc selects rows and columns by their labels. Syntax: df.loc[row_labels, column_labels].

    employees.loc[0, "name"]                     # 'John'
employees.loc[1:3, ["name", "salary"]]       # rows labelled 1 to 3 INCLUSIVE
        name  salary
1   Alex   95000
2   Sara   88000
3  Priya  120000

    Labels become more meaningful with a custom index:

    by_name = employees.set_index("name")
by_name.loc["Sara"]                          # one row -> Series
by_name.loc["Alex":"Priya", "salary"]        # label slice
    name
Alex      95000
Sara      88000
Priya    120000
Name: salary, dtype: int64

    iloc[]: select by position

    Definition: .iloc selects by integer position, counting from 0 like a Python list. Syntax: df.iloc[row_positions, column_positions].

    employees.iloc[0, 0]                 # 'John': row 0, column 0
employees.iloc[0, 1]                 # 25: row 0, column 1 is "age"
employees.iloc[1:3, [0, 3]]          # rows 1 and 2 (end EXCLUDED), columns 0 and 3
       name  salary
1  Alex   95000
2  Sara   88000

    Common mistake

    .loc slices include the end label; .iloc slices exclude the end position, like normal Python. loc[1:3] returned 3 rows above and iloc[1:3] returned 2. Also count positions carefully: in the employee table iloc[0, 1] is the age (25), not the name. The roadmap slide on selection shows John for that call; iloc[0, 0] is the one that returns John.

    at[] and iat[]: one value, fast

    by_name.at["Mei", "salary"]     # 102000, by label
employees.iat[2, 3]             # 88000, by position

    at and iat only fetch or set a single cell, and they skip the overhead of the general indexers. Use them inside rare unavoidable loops.

    Boolean indexing

    Definition: pass a Series of True/False values (a mask) and Pandas keeps the rows where it is True. This is how filtering works.

    mask = employees["age"] > 25        # a boolean Series
employees[mask]
        name  age    department  salary       city
1   Alex   30  Data Science   95000  Bengaluru
2   Sara   28       Product   88000      Kochi
3  Priya   35   Engineering  120000    Chennai
4   Omar   41         Sales   67000  Bengaluru
5    Mei   29  Data Science  102000      Kochi

    Multiple conditions

    employees[(employees["department"] == "Engineering") & (employees["salary"] > 100000)]   # AND
employees[(employees["city"] == "Chennai") | (employees["age"] < 26)]                    # OR
employees[~(employees["city"] == "Kochi")]                                               # NOT
        name  age   department  salary     city
3  Priya   35  Engineering  120000  Chennai

    Use &, | and ~, not Python's and, or and not, and wrap each condition in parentheses. Without them, operator precedence evaluates 25 & employees["salary"] first and you get:

    ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().

    isin() and between()

    employees[employees["city"].isin(["Chennai", "Bengaluru"])]        # value in a list
employees[employees["salary"].between(80000, 100000)]              # inclusive range

    isin replaces a chain of == conditions joined with |. between includes both ends by default; change it with inclusive="left", "right" or "neither".

    query()

    min_salary = 90000
employees.query("department == 'Data Science' and salary > @min_salary")
       name  age    department  salary       city
1  Alex   30  Data Science   95000  Bengaluru
5   Mei   29  Data Science  102000      Kochi

    query takes the condition as a string, which is easier to read for long filters. Reference Python variables with @ and wrap column names containing spaces in backticks. Never build the query string from user input.

    filter()

    Despite the name, DataFrame.filter selects columns or index labels by name, not rows by value:

    employees.filter(items=["name", "city"])     # exact names
employees.filter(like="a", axis=1)           # names containing "a"
employees.filter(regex="^(name|sal)")        # names matching a regex

    It is handy for wide datasets, for example selecting every column that starts with q1_.

    Chapter 8: Data Cleaning and Missing Values

    Data cleaning means fixing or removing data that is missing, duplicated, wrongly typed or inconsistent, before you analyse it. Analysts commonly say it takes most of their time. A wrong total caused by a duplicate row is worse than no total at all.

    Understanding missing values

    Pandas marks missing data with NaN (from NumPy, for floats), NaT (for datetimes), None or pd.NA (for the newer nullable types). The isna family treats all of them as missing.

    raw = pd.DataFrame({
    "name": ["John", "Alex", "Sara", None, "Mei"],
    "age": [25, np.nan, 28, 35, np.nan],
    "department": ["Engineering", "Data Science", None, "Engineering", "Data Science"],
    "salary": [75000, 95000, 88000, np.nan, 102000],
})
print(raw)
       name   age    department    salary
0  John  25.0   Engineering   75000.0
1  Alex   NaN  Data Science   95000.0
2  Sara  28.0           NaN   88000.0
3   NaN  35.0   Engineering       NaN
4   Mei   NaN  Data Science  102000.0

    Notice age and salary became floats (25.0). Classic NumPy integers cannot hold NaN, so Pandas converts the column to float. The nullable Int64 type in Chapter 15 avoids this.

    isna(), isnull(), notna() and notnull()

    raw.isna().sum()                  # missing values per column
raw.isna().sum().sum()            # total missing cells: 5

raw.notna().all(axis=1)           # True for rows with no missing values
    name          1
age           2
department    1
salary        1
dtype: int64

    isnull is an exact alias of isna, and notnull of notna. They exist for historical reasons; pick one pair and use it consistently.

    Common mistake

    df[df["age"] == np.nan] always returns nothing, because NaN is not equal to anything, including itself: np.nan == np.nan is False. Always use isna().

    fillna()

    raw.fillna({
    "age": raw["age"].median(),     # numeric: median ignores extreme values
    "department": "Unknown",        # text: an explicit placeholder
    "salary": 0,
})
       name   age    department    salary
0  John  25.0   Engineering   75000.0
1  Alex  28.0  Data Science   95000.0
2  Sara  28.0       Unknown   88000.0
3   NaN  35.0   Engineering       0.0
4   Mei  28.0  Data Science  102000.0

    Passing a dictionary fills each column differently, which is almost always what you want. Choose the fill value per column based on meaning: 0 is right for "number of returns" and wrong for "salary", where it would drag the average down.

    For ordered data such as sensor readings, carry the last known value forward or the next one backward:

    temps = pd.Series([31.0, np.nan, np.nan, 29.5, np.nan])
temps.ffill().tolist()     # [31.0, 31.0, 31.0, 29.5, 29.5]

    In pandas 3, fillna(method="ffill") raises TypeError: ... unexpected keyword argument 'method'. Use ffill() and bfill().

    dropna()

    raw.dropna()                       # drop rows with ANY missing value -> only John left
raw.dropna(subset=["name"])        # drop only rows missing a name
raw.dropna(thresh=3)               # keep rows with at least 3 non-missing values
raw.dropna(axis=1)                 # drop columns with any missing value

    Plain dropna() kept 1 row out of 5 here. On real data it can silently remove most of your dataset. Use subset to drop only rows missing values you truly need, and compare len(df) before and after.

    interpolate()

    readings = pd.Series([10.0, np.nan, np.nan, 16.0, 18.0])
readings.interpolate().tolist()    # [10.0, 12.0, 14.0, 16.0, 18.0]

    Fills gaps by drawing a straight line between known neighbours. It suits smoothly changing measurements (temperature, stock levels over time), not categories. For time-indexed data, interpolate(method="time") accounts for uneven gaps between timestamps.

    Fixing wrong data types

    A numeric column with one bad value is read as text. Arithmetic on it then fails or, worse, concatenates strings.

    Inconsistent values

    Validating data

    Turn your assumptions into checks that run every time the pipeline runs:

    orders_check = pd.DataFrame({
    "order_id": [1, 2, 3, 3],

    Chapter 9: Data Transformation and Manipulation

    Transformation means deriving new values from existing ones: mapping codes to labels, bucketing numbers, capping outliers, ranking. Pandas offers a ladder of tools, from fast and restrictive to slow and flexible. Climb only as high as you need.

    Vectorised operations: the default

    A vectorised operation works on a whole column at once in compiled code. Arithmetic (+ - * /), comparisons, .str and .dt methods and most built-in methods are vectorised.

    orders["revenue"] = orders["quantity"] * orders["unit_price"]

    I timed four ways to compute price * qty on 1,000,000 rows:

    ApproachTime
    for _, row in df.iterrows() (measured on 100k rows, scaled)about 8.5 s
    df.apply(lambda r: r["price"] * r["qty"], axis=1)2.64 s
    Python zip loop over the two columns0.100 s
    df["price"] * df["qty"]0.74 ms

    The vectorised version was about 3,500 times faster than apply with axis=1. That gap is the single most important performance fact in Pandas.

    map(): transform each value of a Series

    Definition: Series.map replaces each value using a dictionary, a Series or a function.

    codes = {"Engineering": "ENG", "Data Science": "DS", "Product": "PRD"}
employees["department"].map(codes).tolist()
    ['ENG', 'DS', 'PRD', 'ENG', nan, 'DS']

    Values missing from the dictionary ("Sales") become NaN. That is useful for spotting unmapped codes, and a trap if you expected them to stay unchanged; use replace for that.

    employees["salary"].map(lambda s: f"₹{s:,}").head(3).tolist()   # ['₹75,000', '₹95,000', '₹88,000']

    apply(): run a function on values, rows or columns

    def salary_band(salary):
    if salary >= 100000:
        return "high"
    if salary >= 85000:
        return "mid"
    return "entry"

employees["salary"].apply(salary_band).tolist()
    ['entry', 'mid', 'mid', 'high', 'entry', 'high']

    On a DataFrame, apply passes each column (default) or each row (axis=1) to your function:

    employees[["age", "salary"]].apply(lambda col: col.max() - col.min())   # range per column
employees.apply(lambda row: f"{row['name']} ({row['department']})", axis=1)

    ["high", "mid"],
    default="entry",
)

       labels=["entry", "mid", "high"], right=False)

    Chapter 10: Working with Strings

    Text columns expose vectorised string methods through the .str accessor. They mirror Python's str methods but run on a whole column and skip missing values instead of crashing.

    customers = pd.DataFrame({
    "name": ["  john SMITH ", "alex o'neil", "SARA khan", None],
    "email": ["John.Smith@Gmail.COM ", "alex@company.io", "sara.khan@yahoo.com", "bad-email"],
    "phone": ["+91 98470-12345", "98470 55555", "(0484) 2345678", "n/a"],
    "product": ["iPhone 15 Pro - 256GB", "Galaxy S24 - 128GB", "Pixel 9 - 256GB", "iPhone 15 - 128GB"],
})

    Case and whitespace

    customers["name"].str.strip().str.title().tolist()
customers["email"].str.strip().str.lower().tolist()
customers["name"].str.upper().tolist()
    ['John Smith', "Alex O'Neil", 'Sara Khan', nan]
['john.smith@gmail.com', 'alex@company.io', 'sara.khan@yahoo.com', 'bad-email']
['  JOHN SMITH ', "ALEX O'NEIL", 'SARA KHAN', nan]

    strip() removes whitespace from both ends; lstrip() and rstrip() remove it from one side. All three accept characters to remove: pd.Series(["--abc--"]).str.lstrip("-") gives "abc--". Missing values stay missing through the whole chain. Lowercase emails before comparing or deduplicating them.

    replace()

    customers["phone"].str.replace(r"\D", "", regex=True).tolist()           # keep digits only
customers["product"].str.replace(" - ", " | ", regex=False).tolist()     # literal text
    ['919847012345', '9847055555', '04842345678', '']
['iPhone 15 Pro | 256GB', 'Galaxy S24 | 128GB', 'Pixel 9 | 256GB', 'iPhone 15 | 128GB']

    Always pass regex= explicitly. \D means "any non-digit", so the first line normalises phone numbers in every format to digits.

    split()

    parts = customers["product"].str.split(" - ", expand=True)
parts.columns = ["model", "storage"]
print(parts)

    Without expand=True, each cell holds a list. With it, each piece becomes its own column. Use n=1 to split only on the first separator.

    contains(), startswith(), endswith() and len()

    customers["product"].str.contains("iphone", case=False).tolist()     # [True, False, False, True]
customers["product"].str.startswith("Pixel").tolist()                # [False, False, True, False]
customers["email"].str.strip().str.lower().str.endswith(".com").tolist()
customers["name"].str.len().tolist()                                 # [13.0, 11.0, 9.0, nan]
customers["name"].str.contains("john", case=False, na=False)         # missing -> False

    These return boolean masks for filtering: customers[customers["product"].str.contains("iphone", case=False)]. contains treats the pattern as a regex by default; pass regex=False when searching for text containing ., + or (. Pass na=False so missing values do not break the filter.

    extract(): pull structured data out of text

    customers["product"].str.extract(r"(?P<storage_gb>\d+)GB")

    Each regex capture group (the part in parentheses) becomes a column, and ?P<name> names it. Rows with no match get NaN. extractall returns every match, not just the first.

    match() and fullmatch()

    pattern = r"^[\w.+-]+@[\w-]+\.[\w.]+$"
customers["email"].str.strip().str.match(pattern).tolist()      # [True, True, True, False]

    match anchors at the start of the string only; fullmatch requires the whole string to match, so you can drop the ^ and $. contains searches anywhere. For validation, prefer fullmatch.

    Slicing and joining

    Chapter 11: Grouping and Aggregation

    What is GroupBy?

    GroupBy answers "per something" questions: revenue per region, average salary per department, orders per customer. It follows a pattern called split-apply-combine:

    Copy vs view, and Copy-on-Write

    Before pandas 3, whether a selection returned a view (sharing memory with the original) or a copy depended on internal details. Changing a subset sometimes changed the original and sometimes did not, and Pandas warned with the infamous SettingWithCopyWarning.

    pandas 3 makes Copy-on-Write (CoW) the only behaviour. The rule is now simple: every DataFrame or Series you get from an operation behaves as an independent copy. Internally Pandas still shares memory and copies only when one side is modified, so it is cheap.

    The one pattern that now never works is chained assignment, assigning through two indexing steps:

    emp[emp["name"] == "John"]["salary"] = 1      # does nothing
    ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment ...

    It is a warning, not an exception, and John's salary stayed 75000. The first indexing step creates a new object, and the assignment modifies that temporary object. The fix is always one .loc call:

    emp.loc[emp["name"] == "John", "salary"] = 80000     # works

    Upgrading from pandas 2

    • Defensive .copy() calls after filtering are no longer needed to avoid warnings. They are harmless but cost memory.
    • Code that relied on a subset modifying its parent now silently does not. Search for chained assignments before upgrading.
    • Run your test suite on pandas 2.2 with pd.options.mode.copy_on_write = "warn" first; it flags code whose behaviour will change.

    Faster filtering and queries

    • Filter as early as possible, ideally in SQL or with usecols and Parquet filters, so less data reaches Pandas.
    • Select columns before groupby: df.groupby("k")["v"].sum(), not df.groupby("k").sum()["v"].

    Chapter 18: Performance and Best Practices

    The rules that matter most

    1. Prefer vectorised operations. Column arithmetic ran in 0.74 ms where apply(axis=1) took 2.64 s (Chapter 9).
    2. Avoid loops over rows. iterrows() was the slowest option measured. If a loop is truly unavoidable, itertuples() is much faster than iterrows(), and a loop over NumPy arrays (df["a"].to_numpy()) faster still.
    3. Use appropriate data types. Read IDs as strings, dates as datetimes, and numbers as numbers. Wrong types are slower and cause bugs.
    4. Optimise memory. Downcast numbers and load only the columns you need. Memory use went from 16.0 MB to 5.0 MB in Chapter 15.
    5. Use categoricals for repetitive text. 14.4 MB to 1.0 MB for a city column.
    6. Avoid unnecessary copies. With Copy-on-Write, extra .copy() calls are no longer needed for safety. Do not keep five intermediate versions of a large DataFrame alive; reuse names or chain methods.
    7. Read large files in chunks when they do not fit in memory, or convert them to Parquet once.
    8. Filter early. Push filters into SQL, usecols or Parquet reads before data reaches Pandas.
    9. Do not grow DataFrames in a loop. Collect rows in a list and build the frame once.
    10. Benchmark before optimising. Guesses about performance are often wrong.

    When Pandas is not the right tool

    Pandas works in memory on one machine. As a rough guide, it needs several times the file size in RAM while working. Its limits:

    • Datasets larger than available memory.
    • Many common operations use only one CPU core.
    • Heavy row-by-row logic that cannot be vectorised.
    • Transactional, multi-user data. That belongs in a database.

    Silent problems (no error, wrong answer)

    These are worse than exceptions, because nothing tells you something went wrong.

    • Numbers stored as text. pd.Series(["10", "20", "30"]).sum() returns '102030', string concatenation. Check dtypes after every read.
    • Row explosion after a merge. Duplicate keys on both sides multiply rows. Compare len() before and after, and use validate=.
    • Missing values skipped in maths. pd.Series([1, None, 3]).mean() is 2.0, not 1.33, and the sum of an all-missing column is 0. Decide deliberately how missing values should count.
    • Comparing with NaN. == np.nan is always False. Use isna().
    • Ambiguous dates parsed in the wrong order (Chapter 13).
    • Integer columns turning into floats when one value is missing; IDs then print as 101.0. Use Int64.

    Performance problems

    If a script is slow, check in this order: a Python loop or apply(axis=1) over rows; growing a DataFrame inside a loop; reading the same file repeatedly; text columns that should be category; and loading columns or rows that a filter later throws away.

    Chapter 20: Pandas Interview Preparation

    Basic questions

    1. What is Pandas and what are its main data structures?

    An open-source Python library for structured data. Its main structures are the Series (one-dimensional, labelled) and the DataFrame (two-dimensional, labelled rows and columns, each column a Series).

    2. How do you read a CSV and inspect it?

    df = pd.read_csv("file.csv"), then df.shape, df.info(), df.head() and df.describe().

    3. How do you select rows where a column meets a condition?

    Boolean indexing: df[df["age"] > 30]; for several conditions, df[(cond1) & (cond2)]; or df.query("age > 30").

    4. How do you find and handle missing values?

    df.isna().sum() to find them; fillna to replace (per-column values, ffill, interpolation) or dropna(subset=...) to remove. The right choice depends on what the column means.

    5. What is the index?

    The row labels. It identifies rows, drives .loc lookups and aligns data in arithmetic, joins and assignments.

    Intermediate questions

    6. Explain split-apply-combine.

    GroupBy splits rows into groups by key, applies a function to each group (aggregate, transform or filter) and combines the results into one object.

    7. What is the difference between agg and transform?

    agg returns one row per group. transform returns a result the same length as the input, aligned to the original rows, so you can add a group statistic as a new column.

    8. How do you remove duplicates while keeping the latest record?

    df.sort_values("updated_at").drop_duplicates(subset="customer_id", keep="last").

    9. How do you convert a column to datetime and get monthly totals?

    df["date"] = pd.to_datetime(df["date"], format=...), then df.resample("ME", on="date")["amount"].sum().

    10. How do you reshape wide data to long?

    df.melt(id_vars=[...], var_name=..., value_name=...). The reverse is pivot or pivot_table.

    Advanced questions

    11. What is Copy-on-Write and how did pandas 3 change things?

    Every derived DataFrame or Series behaves as an independent copy; data is physically copied only when one side is modified. It is the only mode in pandas 3. SettingWithCopyWarning is gone, and chained assignment (df[a][b] = x) never updates the original. Use a single .loc.

    12. How would you process a 20 GB CSV on a laptop with 16 GB RAM?

    Read only needed columns with explicit dtypes, process with chunksize and combine partial aggregates, or convert once to Parquet and read selected columns. If the logic needs the whole dataset (joins, medians), use DuckDB or Polars' lazy mode, or Dask.

    13. Why is apply(axis=1) slow, and what do you use instead?

    It calls a Python function once per row and builds a Series for each row. Replace it with vectorised column operations, np.where/np.select for conditions, pd.cut for bins, and map with a dictionary for lookups.

    14. How do you reduce a DataFrame's memory?

    Measure with memory_usage(deep=True), then downcast numbers, convert low-cardinality text to category, use the str or Arrow-backed types instead of object, and drop unused columns.

    15. How do you replicate a SQL window function?

    groupby().transform() for SUM() OVER (PARTITION BY ...), groupby().cumcount() for ROW_NUMBER(), groupby().rank() for RANK(), groupby().shift() for LAG(), and groupby().rolling() for moving windows.

    Scenario-based questions

    16. After merging orders with customers, your revenue total went up. Why?

    The customer table has duplicate keys, so some orders matched several customer rows and were counted more than once. Check customers["customer_id"].duplicated().sum(), deduplicate, and add validate="many_to_one" to the merge.

    17. A column of amounts sums to a huge string. What happened?

    It was read as text, probably because of a currency symbol, thousands separator or a stray value. Clean the text and convert with pd.to_numeric(..., errors="coerce"), then investigate the rows that became NaN.

    18. A daily report shows no row for days with zero sales. How do you fix it?

    Use resample("D"), which includes empty periods, or reindex against pd.date_range(start, end, freq="D") with fill_value=0.

    Frequently Asked Questions

    Is Pandas hard to learn?

    The basics take a few days if you know Python: reading files, selecting, filtering, grouping. Fluency comes from using it on real, messy data. Start with the roadmap concepts, then move to groupby, merge and dates.

    Do I need NumPy before learning Pandas?

    No. Knowing that operations work on whole arrays at once (vectorisation) helps, and you will pick up the few NumPy functions you need, such as np.where and np.nan, along the way.

    Should I learn Pandas or Polars in 2026?

    Learn Pandas first. Most tutorials, libraries and existing codebases use it, and job descriptions ask for it. Polars is worth adding when performance becomes a problem; the concepts carry over directly.

    How much data can Pandas handle?

    As much as fits comfortably in memory, usually a few million to tens of millions of rows on a laptop. Efficient dtypes, column selection and chunking stretch that further.

    Is Pandas used in backend development?

    Yes: bulk imports and exports, data migrations, reports, reconciliation jobs and admin analytics. Run heavy Pandas work in background workers such as Celery rather than inside web requests.

    What changed in pandas 3.0?

    Copy-on-Write is always on, text columns default to the new str dtype, and deprecated APIs were removed, including DataFrame.applymap, fillna(method=...) and the "M", "Q" and "Y" frequency aliases. The official migration guide lists every change.

    Conclusion

    Pandas turns tabular data work into short, repeatable code. The core is small: Series and DataFrames, reading and inspecting data, selecting with loc and iloc, cleaning missing and messy values, groupby for summaries and merge for combining sources. Dates, reshaping, window functions and memory tuning build on that foundation.

    Three habits matter more than any single method: vectorise instead of looping, check dtypes and row counts after every read and merge, and on pandas 3 update data with one .loc call. Pick a real CSV from your own work, run the five-minute exploration checklist from Chapter 5, and build one of the projects above on it.
